# Hi-fi design

## Process

1. Ask questions. Many of them.
2. Find existing UI kits and collect design context. Copy in every relevant component, read every relevant example. Ask LO if you cannot find them.
3. Start the file with assumptions, context, and design reasoning - as a junior designer writing for their manager - with placeholders where the designs will go. Show it early.
4. Build the designs and show them again as soon as they are real. Append next steps.
5. Check, verify, and iterate with your own tools before handing over.

## Design context is not optional

Good hi-fi work does not start from scratch. Ask LO to import his codebase, or find a suitable UI kit, or ask for screenshots of the existing UI. Spend real effort acquiring context, components included. Be proactive: list design assets, look through design system files, check whether more than one design system is in play and get them all. Use the starter frames (device bezels, window chrome) for high-quality scaffolding for free.

Recreating UI from code beats recreating it from screenshots every time. Screenshots are a high-level guide; the source is the truth. Mocking a full product from scratch is a last resort and produces poor design.

## Variations

Give three or more variations across several dimensions. Mix by-the-book options that match existing patterns with novel interactions, layouts, metaphors, and visual styles. Some with color and advanced CSS, some with iconography and some without. Start basic and get more adventurous down the list.

Remix the brand's visual DNA: play with scale, fills, texture, visual rhythm, layering, unusual layout, type treatment. The goal is not one perfect option; it is atomic variations LO can mix and match.

For several options on one page, choose between one full-size responsive prototype with tweaks, or the vertical stack of anchored option cards from the `design-options` skill. Judge by how design-y versus prototype-y the ask is, how many options there are, and how large each one is.

When LO asks for new versions later, prefer adding them to the existing Design Component - as extra screens, sections, or a small in-design switcher - rather than forking into many files.

## Standards

CSS, HTML, JS, and SVG can do more than most people expect. Surprise LO.

If you do not have an icon, asset, or component, draw a placeholder. In hi-fi work a clearly marked placeholder beats a bad imitation of the real thing.
